Follow this theorem-proving workflow unless a narrower runtime instruction overrides it:

- Phase 1 comes first: build a theorem-level skeleton before trying to finish local proofs. Use a two-layer split: semantic nodes for real mathematical claim changes, then Coq-friendly shape nodes for target-shape changes needed to prove each semantic node.
- Read the target theorem and any provided proof narrative before deep search.
- If the current theorem workspace contains `proof.tex`, read it first and use it as evidence for the informal proof while it is concrete enough to guide the split. If it is vague, incomplete, mismatched with the theorem statement, or too compressed for Coq obligations, explicitly downgrade it and build the split from the theorem statement, hypotheses, live goals, imported definitions, and existing Prosa/MathComp proof patterns.
- A semantic node should record a genuine mathematical claim change: a new bound, case distinction, existence claim, uniqueness/counting claim, semantic scheduling fact, contradiction setup, or final implication. Do not create semantic nodes for purely syntactic Coq transport.
- A shape node should change exactly one Coq proof representation or library-alignment shape. Typical kinds include `shape_transport`, `witness_transport`, `injectivity_uniq`, `library_instantiation`, `semantic_bridge`, `pointwise_semantic_bridge`, `definition_rewrite`, `case_split_boundary`, `contradiction_close`, and `final_arithmetic`.
- Use `pose` or `set` for objects only when naming them supports later semantic or shape nodes. Use `have`, `assert`, `suff`, or `enough` for proposition nodes; prefer `suff`/`enough` when the node is a target-shape bridge that reduces the parent goal.
- Each generated node must have a contract comment with at least `plan_node`, `kind`, `depends_on`, `source`, `input`, `output`, `layer`, `expected`, `normal_form`, and `evidence` fields. The `expected` field should name the likely proof method or library class, such as a Prosa semantic fact, MathComp shape lemma, local hypothesis, compiler-certified dependency, arithmetic, contradiction, or local rewriting. The `evidence` field must name a concrete source using `prosa:`, `mathcomp:`, `local:`, `context:`, `coq:`, or `compiler:` as appropriate; do not invent a library citation for a purely local fact.
- Use a generic route recipe as soft planning guidance: prepare only necessary definitions/context, establish a semantic or pointwise bridge, normalize the library-facing data/collection shape, aggregate established facts, then close the final logical or arithmetic composition. This recipe is not theorem-specific and may be reordered, merged, replaced, or abandoned when the live goal and compiler evidence support a better route.
- Prefer roughly 3-6 meaningful first-level regions, commonly 4-5, but never reject a sound plan merely for having a different count. A region should export one useful fact, declare complete dependencies, and be independently certifiable while still allowing several local rewrites, arithmetic steps, or same-region helpers.
- Split a region when it mixes independent semantic layers, hides an unavailable premise, spans cross-branch ownership, or repeatedly fails with the same semantic/compiler signature. Merge adjacent micro-regions when they merely perform consecutive normalization or arithmetic steps under the same hypotheses and cannot provide useful independent certificates.
- A `paper_bridge` kind, `layer: paper`, or `layer: theorem_spine` proof_region is not lemma-ready. It is a planning artifact that Layer 1 must refine into smaller leaves such as `semantic_bridge`, `count_cardinality`, `shape_transport`, `definition_rewrite`, `library_instantiation`, or `final_arithmetic` before any lemma delegation.
- An internal multi-step proof is allowed inside one region when all steps serve the same exported fact and use the same dependency boundary. Do not split merely because the local proof has several tactic steps.
- Do not satisfy decomposition with dummy claims such as `have H : True` or comment-only placeholders. Every named local step must state its intended Coq object or proposition.
- Do not satisfy decomposition by admitting a compound parent claim directly. If a high-level equality, inequality, case branch, or final bridge summarizes several semantic or shape changes, open its proof body and introduce nested local `pose`s, `set`s, `have`s, `assert`s, `suff`s, case splits, and bridge facts for those changes.
- Parent claims and case branches must contain a final composition step that combines their nested child facts. The final theorem goal must be closed by combining the top-level skeleton facts; a trailing top-level `admit` after the facts have been named is not a completed Phase 1 skeleton.
- Do not introduce theorem-shaped or parent-shaped admitted facts. A `have` or `assert` whose conclusion is the current theorem goal, a near-final reformulation of it, or a parent conclusion that should be composed from existing child facts must be proved in Layer 1 rather than delegated or admitted.
- When a proof step introduces witnesses, partitions, complements, cases, or branches, wire those concrete objects into subsequent proof steps: destruct witnesses, name membership, disjointness, cover, cardinality, and rewrite facts, case split on concrete branch conditions, and use branch-local facts to close parent claims.
- Avoid detached universally quantified helper claims when the informal or context-derived proof is about concrete objects already introduced by earlier steps. Keep the concrete proof flow visible unless a genuinely reusable local fact is needed.
- Every theorem hypothesis that the informal or context-derived proof relies on should appear in the outer skeleton as a named derived fact, branch premise, bridge premise, or composition argument before the relevant local gap is delegated.
- Use `proof_plan` to extract the semantic spine as a proof DAG, audit proof.tex usefulness, or clarify a context-derived split; it does not replace writing the actual skeleton and contract-bearing DAG nodes back to the file.
- The Phase 1 output should be a pasteable Coq skeleton that pushes the main proof as far as possible, ideally until the final theorem goal is closed and only admitted leaf subproofs remain, producing the equivalent of `No more goals, but there are some goals you gave up`.
- Layer 1 is the theorem-level splitter. It owns the semantic spine, Coq-friendly shape-node decomposition, first-level gap contracts, and the decision that a gap is local enough to delegate.
- Layer 2 is the local gap prover. It owns exactly one assigned first-level block after the split and may only decompose further inside that assigned block.
- In Layer 2, local decomposition is strict prefix-order. Within the assigned proof_region, the first unresolved `admit` or empty `{}` is the only proof hole the lemma agent may fill; later local `have`/`assert`/`suff`/`enough` bodies must remain untouched until the current hole has validated.
- When a first-level local gap is isolated and ready for delegated local proof, write it as a `proof_region begin/end` with one stable `admit_id` or gap identifier. The begin marker, or the immediately preceding contract comment, must materialize the proof DAG node with `plan_node`, `depends_on`, `source`, `input`, `output`, `layer`, `expected`, `normal_form`, and grounded `evidence`; otherwise the runtime locality gate will hand it back to Layer 1 for remodeling. The markers must wrap the exported local target statement, including its proposition, and its complete `{ ... }` proof block; do not put the markers only inside that target's braces. Keep architecture-sensitive, parent-level, cross-branch, or dependency-incomplete work in Layer 1, but do not fragment a coherent locally certifiable fact into tactic-sized leaves.
- Because Layer 1 often cannot know the final local proof script before proving it, `proof_region begin/end` is the sole delegation boundary. It lets the local prover write proof text and add same-region sibling helper `pose` / `have` / `assert` statements before the exported target. The region is the editable boundary for the complete local target declaration and proof block, but the exported target statement is the prover-authored subgoal contract and should be preserved whenever possible; text outside it remains Layer 1-owned.
- Once first-level `proof_region owner: lemma` markers exist, do not continue proving inside those frozen gaps in Layer 1; the runtime scheduler mechanically enqueues one dependency-ready lemma-owned gap with a complete `lemma_assignment`. Declared producer regions must be compiler-certified first. File order is only a deterministic tie-breaker among ready regions, so an unrelated difficult earlier region does not block an independent later region.
- After all lemma-owned regions are solved, return to Layer 1 for final merge and final validation. The last lemma task must not close the outer theorem or replace the theorem-level `Admitted.` with `Qed.` because that terminator is outside the lemma editable region.
- If a candidate gap needs a missing theorem-level bridge, an explicit context bridge derived from existing hypotheses, or a change to the outer proof spine, do not delegate it as a lemma-owned local block. Keep it in Layer 1 and state the exact bridge obligation instead. `needs_context_strengthening` must not mean strengthening the theorem statement or adding section-level, theorem-level, or global assumptions.
- In normal Phase 2 discharge, the theorem-level skeleton is frozen; a difficult or long local proof is not evidence for changing it. Enter structural-escalation repair only with concrete evidence such as a wrong target shape, missing theorem-level bridge, non-local/cross-branch obligation, sibling syntax blocker, or outer-spine mismatch.
- If a delegated lemma returns a structural escalation such as `needs_subgoal_remodel`, `needs_preceding_bridge`, `needs_uniqueness_bridge`, `needs_context_strengthening`, `needs_theorem_spine_change`, `blocked_by_sibling_syntax`, or `not_local`, do not redispatch the same stale `admit_id`; renaming or versioning `admit_id`, markers, comments, or whitespace is not repair progress and must not be used to evade the repeated blocker. First review the stable blocked goal, missing premise, remodel request, attempt report, or actual checkpoint `Error:` diagnostic, then remodel the region, add the missing theorem-level bridge, or revise the theorem spine only when that evidence requires Layer 1 repair.
- After reading the theorem, proof narrative when useful, and the small directly relevant set of supporting facts needed for the next semantic or shape-node contract, the next non-validation action must be a file edit or proof step that you promptly write back.
- Do not take two consecutive broad read or search batches while the proof file is unchanged.
- For one Layer 1 theorem-level blocker, you may do at most one broad blocker lookup batch, then up to three narrow bridge lookups or instantiations. Each narrow step must be tied to that blocker and immediately followed by a concrete edit or a `coq_session` step whose result you write back. This Layer 1 lookup discipline does not cap a delegated lemma agent's long-running direct proof loop.
- Before concluding that a claim is impossible, false, or based on a wrong file, audit the exact theorem statement, local hypotheses, section or context declarations, imports, and the live goal or hypotheses currently visible in Coq.
- Do not add new section-level, theorem-level, or global assumptions outside the proof.
- Do not use ssreflect repeat-rewrite syntax `rewrite !...` or `rewrite -!...`; write repeated rewrites explicitly one step at a time, or introduce a named normalization/bridge lemma.
- Do not use the `intuition` tactic; it generates opaque proof terms and is rejected. Use explicit tactics (`left`/`right`/`split`/`apply`/`exact`) instead.
- Do not invent a new theorem-level story while `proof.tex` is concrete and still applicable. If it is not concrete enough to determine Coq obligations, say so in the skeleton comments, downgrade it, and build the semantic spine and shape-node contracts from the theorem context.
